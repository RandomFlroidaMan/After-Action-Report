# ADR 0001: Local-first PostgreSQL, explicit canon governance

Status: accepted for the initial vertical slice.

Use a pnpm TypeScript workspace and Next.js server API. Keep domain services independent from HTTP. Node's existing test runner exercises the same services with a real embedded PostgreSQL engine, rather than mocking database authorization.

PGlite removes account and Docker requirements from the private local demo while retaining PostgreSQL SQL and RLS. Network PostgreSQL is selectable for concurrent processes and the standalone worker. Docker Compose supplies a local network DB. Dependencies are pinned and pnpm has explicit esbuild/sharp build allowances.

Use a small SQL job queue before adding Redis. Keep the package graph direct until several apps warrant Turborepo task caching. Use CSS with semantic accessible controls rather than adding a UI framework for the first screen set. This differs from the recommended Tailwind/Turbo stack without changing domain boundaries.

Canonical projection updates are approved, optimistic-locked and transactional. Source evidence, final decisions, ledger entries, audit events and published reports are immutable. A correction is a proposal plus a compensating ledger event or a new fact revision, never transcript rewriting.

Tradeoffs: local storage is not encrypted object storage; the initial queue holds locks while providers run; embedded DB mode is single-process. Do not horizontally scale it. A production deployment needs the additional controls in SECURITY.md.
